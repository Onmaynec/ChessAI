# Chess AI v0.7.0 — Training Performance & Intelligence

Локальная шахматная исследовательская система: C++20 Chess Core, собственная policy/value сеть PyTorch, PPO self-play и Training Studio. **Веса и кодировщик шахматных позиций совместимы с v0.6.0** (`planes19_actions73_v1`). **Никакая модель не становится сильнее автоматически от одного обновления версии** — качество проверяйте отдельно через Holdout Evaluation.

## Важно: как обновиться и не потерять 500+ итераций

1. В старой Training Studio нажмите **Остановить после итерации**, дождитесь записи `latest.pt` и завершения Python процесса. **Не закрывайте окно посреди записи checkpoint.**
2. Сделайте независимую резервную копию `runs/` (или старой установки). Перед очисткой убедитесь, что `runs/<ID>/checkpoints/latest.pt` существует. Старую папку не удаляйте.
3. Распакуйте этот ZIP **отдельно**, в `ChessAI-v0.7.0`. **Не поверх старой версии.**
4. Запустите `UPGRADE_FROM_CURRENT.bat` и укажите полный путь к корню установленной v0.6.0, даже если он переименован. Установщик сначала проверяет файлы и конфликты, затем копирует сохранения с SHA-256. Старую папку **не трогает**. **Для копии больших логов первоначально нужно свободное место на диске.**
5. Если старая папка содержит `.venv-cuda/Scripts/python.exe`, мигратор настроит `config/python_path.txt`: **будет использована старая CUDA-среда без копирования огромного Torch**. Старая папка должна оставаться на месте, пока используется этот интерпретатор.
6. Запустите `scripts/VERIFY_PROGRESS_WINDOWS.bat`: он проверит итерацию, весовую архитектуру, оптимизатор и историю метрик. Убедитесь, что это **номер последнего сохранённого checkpoint**, а не ноль.
7. Для освобождения места запустите `scripts/COMPACT_RUNS_WINDOWS.bat`, введите ID эксперимента и подтвердите `YES`. Вы увидите размер до и после. Скрипт не удаляет веса, оптимизатор, checkpoint и историю метрик.
8. Запустите `START_CHESS_AI.bat`. В интерфейсе проверьте `BUILD 0.7.0`, выберите старый эксперимент и сделайте **1–2 пробные итерации**, затем повторите `VERIFY_PROGRESS_WINDOWS.bat`.

**Не запускайте старую и новую Training Studio одновременно.** Убедитесь, что предыдущий `python -m neural.selfplay` действительно остановлен. Не удаляйте старый проект до проверки новой версии и резервной копии.

Подробно: [docs/UPGRADE_TO_0.7.md](docs/UPGRADE_TO_0.7.md).

## Что сделано в v0.7.0

### Безопасное дисковое архивирование (главное изменение)

Раньше `experience.jsonl`, `games.jsonl` и `arena_games.jsonl` росли в текстовом виде при каждой итерации. Теперь завершённые журналы сжимаются **без потерь** в `runs/<ID>/archives/{experience,games,arena_games}/` (gzip). Оригинальные байты проверяются **SHA-256 при обратном распаковывании** до удаления несжатой копии. Весь обучающий опыт и игры остаются доступными; архивы не являются новым форматом нейросети.

- На реальной копии эксперимента с 170 итерациями размер снизился **с 325,82 до 92,29 МиБ**, с сохранением 703 470 записей опыта. Сжатие других запусков может отличаться.
- После этого та же модель **успешно продолжилась с итерации 170 до 171**, сохранив оптимизатор, а просмотрщик игр способен читать старые архивы.
- Автоматическое сжатие по умолчанию раз в **5 завершённых итераций** (`--archive-every 5`), только после записи checkpoint и метрик. Для отключения `--archive-every 0`.
- Чтобы уплотнить старую крупную папку **без продолжения обучения**, воспользуйтесь `scripts/COMPACT_RUNS_WINDOWS.bat` после остановки. Из панели: Диагностика → Место на диске → «Сжать журналы».
- Исторические `iteration_XXXXX.pt`, `best.pt`, `latest.pt`, `metrics.jsonl`, `run_metadata.json`, `run_state.json` **не удаляются и не сжимаются**. Старые контрольные модели остаются доступны лиге и турнирам.
- Повторная архивация безопасна; при обрыве между публикацией gzip и удалением исходника код сверяет контрольную сумму, прежде чем убрать дубликат.
- При восстановлении прерванных журналов применяется **потоковый алгоритм**, чтобы избежать загрузки гигабайт опыта в RAM; исходный журнал сначала резервируется в проверенном gzip-файле в `recovery/`.

Для ручного запуска из корня:

```powershell
.\.venv-cuda\Scripts\python.exe -m tools.compact_runs --run runs\run_20261123_072154_6a110b
.\.venv-cuda\Scripts\python.exe -m tools.compact_runs --run runs\run_20261123_072154_6a110b --apply
```

Если CUDA-Python остался в старой папке, используйте `.bat`, он автоматически найдёт выбранный интерпретатор. `--apply` **не сработает, если `run_state` всё ещё помечен как running**. Остановите обучение корректно.

### CPU + GPU: непрерывное пакетирование и C++ workers

- `rollout()` больше не ждёт, пока завершится **самая долгая партия всей волны**: освободившиеся слоты сразу заполняются новыми партиями. Сеть оценивает позиции одновременно готовых игр за один inference batch.
- `--bridge-workers 2` по умолчанию — несколько **независимых C++ chess bridge процессов**, параллельное выполнение ходов на CPU через пул потоков Python, без конкурентного чтения одного stdin pipe. Допустимые значения 1–8.
- `--parallel 8/16/32` — число одновременных партий, отдельное от `--batch-size 64` (размер минибатча PPO). Начните со значения **16 партий** при `games-per-iteration=16`, затем измеряйте реальное время на вашем Ryzen 5 5600 и RTX 3050.
- Новые поля `performance` в `metrics.jsonl`: `opening_s`, `bridge_steps_s`, `neural_inference_s`, `ppo_s`, `arena_s`, `average_inference_batch`, `max_inference_batch`, `bridge_workers`, `concurrent_games` и `total_iteration_s`. Отображаются в панели диагностики.
- Бенчмарки проводятся только на собственном ПК: **никаких обещаний ускорения в X раз**. Маленькая сеть и обмен CPU/GPU способны стать узким местом даже при 100% загрузке одного движка GPU.

### CUDA после обновления

Когда в мигрируемой установке уже была `.venv-cuda` с `torch==2.15.0+cu134`, новой установке **не требуется качать те же 2,2 ГБ ещё раз**. `START_CHESS_AI.bat` использует указанный в `config/python_path.txt` абсолютный путь; Training Studio передаёт текущий `sys.executable` дочерним процессам. Если путь устарел, отредактируйте `config/python_path.txt` или установите окружение в новой папке. **Не копируйте `.venv-cuda` как обычную папку** — virtualenv может содержать жёсткие пути.

### Качество обучения

- PPO, весовые checkpoint и схема наград **не изменены**; это снижает риск незаметного сброса или смены обучающей задачи.
- `best.pt` остаётся отдельно от `latest.pt`, контролируемые проверочные матчи продолжают работать.
- Оценку реальной силы проводите **Holdout Evaluation**, а не делайте выводы из падения loss или высокой загрузки GPU.

## Как запустить

**Windows**: `START_CHESS_AI.bat` → `http://127.0.0.1:8765`. Требуются CMake + C++ Build Tools/Visual Studio, Python и зависимости `requirements.txt`. Если порт занят старым процессом, закройте его перед запуском. Для CPU можно использовать `.venv`; для NVIDIA нужен подходящий CUDA PyTorch.

**Проверки**: `scripts/VERIFY_PROGRESS_WINDOWS.bat`; `scripts/BENCHMARK_HARDWARE_WINDOWS.bat`; `scripts/AUDIT_COLOR_WINDOWS.bat`; `scripts/EVALUATE_RUN_WINDOWS.bat`; `scripts/CHECKPOINT_TOURNAMENT_WINDOWS.bat`.

**Тесты в среде разработки**: Python `unittest discover -s tests`, CMake + CTest. Windows `.bat` и CUDA на физической RTX 3050 в тестовом контейнере не запускались.

Шахматная система предназначена для обучения и игры в разрешённых окружениях. Не используется для скрытого управления человеческими аккаунтами на соревновательных шахматных сайтах.
