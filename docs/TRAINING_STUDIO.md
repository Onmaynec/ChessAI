# Training Studio — использование панели мониторинга

**Старт (Windows):** дважды нажмите `START_CHESS_AI.bat`, затем откройте `http://127.0.0.1:8765`. Скрипт попробует собрать C++-ядро и установить Python-пакеты при необходимости.

## Экран «Обзор»

- Заголовок: имя активного запуска, состояние, процессорное/GPU устройство, размер модели.
- Прогресс: **завершённые** итерации (checkpoint сохранён) из запланированных.
- Фаза: `selfplay`, `optimization`, `arena` или `ready`, количество собранных партий текущей итерации.
- Карточки: `games`, `finished`, `plies`, `samples` — последние означают только позиции из завершённых игр с известным исходом.
- Графики: Value MSE / Policy loss / entropy (переключатель); скорость симуляции в полуходах в секунду.
- Круговая диаграмма: победы белых, победы чёрных, ничьи, незавершённые отдельно.
- Arena score: результат против сохранённой модели v0.2 с указанием выборки.

## Экран «Партии и анализ»

Выберите тип «Self-play» или «Проверочные», затем при необходимости фильтр исхода. Нажмите «Открыть» рядом с партией — появится доска в сохранённых FEN, история UCI-ходов и причина завершения. Можно двигать ползунок, переходить по кнопкам и нажимать конкретные ходы.

**Важное ограничение:** список показывает последние 50 подходящих записей из последних 5000. Старые записи могут находиться в `archives/{games,arena_games}/*.jsonl.gz`; интерфейс умеет читать их по запросу. Система не анализирует качество каждого хода сильным шахматным движком — это просмотр реальной истории, а не оценка blunder/mistake.

## Экран «История запусков»

Тесты, полноценные тренировки и прежние продолжения сохраняются в `runs/<id>`. Запуск можно выбрать в выпадающем списке или на карточке. В консоли показываются последние строки реального процесса. Для экспортирования метрик используйте `http://127.0.0.1:8765/api/export/metrics.csv?run=ИМЯ_ЗАПУСКА`.

## Как начать новый эксперимент

«Новое обучение» → пресет или ручные параметры → «Запустить». По умолчанию используется готовый checkpoint v0.2. Большое число одновременных досок нагружает CPU, а при CUDA — также GPU. Если данные загрузки не появляются, проверьте строку подключения к C++ ядру и журнал `console.log`.

«Остановить после итерации» создаёт запрос на безопасную остановку. Программа **не прерывает текущую партию немедленно**, чтобы не терять checkpoint. Когда процесс завершился, «Продолжить обучение» попросит количество дополнительных итераций. Веса прошлого этапа и optimizer восстановятся из `checkpoints/latest.pt`.

## Диагностика Windows

- Если нет CMake или `cl.exe`, установите Visual Studio C++ workload.
- Если `python` не обнаружен, установите Python 3.11+ x64 и проверьте `py -3 --version`.
- Если `torch.cuda.is_available()` возвращает `False`, проверьте CUDA wheel PyTorch на официальном сайте.
- Если localhost:8765 занят, запустите `.venv\Scripts\python.exe -m dashboard.server --port 8766 --no-browser` и откройте http://127.0.0.1:8766.
- Если видна нулевая выборка `samples`, причина обычно в незавершённых партиях. Увеличьте лимит полуходов, количество игр или проведите тренировку на подходящих эндшпильных позициях.

Доступ к API управления обучением **не требует авторизации**: разработано для персонального localhost, не публикуйте панель в интернет.

## v0.7.0: дисковое пространство и профилирование

Диагностика модели → **Место на диске и архивирование** показывает несжатые журналы, gzip-архивы, checkpoint и прочие файлы. Кнопка «Сжать журналы» работает только при остановленном обучении; история партий и данные опыта остаются побайтно восстановимыми из SHA-256-проверенных архивов.

Блок **CPU и GPU — время этапов** показывает раздельное время C++ bridge, GPU/PyTorch inference, PPO, Arena и средний размер нейросетевого пакета. Показатели появляются для новых итераций v0.7.0. Не делайте выводов о силе игры из загрузки видеокарты или скорости генерирования партий.
