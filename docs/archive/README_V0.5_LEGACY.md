# Chess AI v0.5.0 — Intelligence Recovery

Локальный экспериментальный шахматный ИИ: собственное C++20 ядро правил, policy/value-сеть PyTorch, обучение PPO на self-play и браузерная Training Studio. Никакие платные AI API не используются. Основная платформа — Windows 10/11; исходники тестируются также на Linux.

**Важное:** это исследовательский прототип. Ни рейтинг Elo, ни объективный прирост силы в v0.5.0 не гарантированы. Последний checkpoint `latest.pt` нужен для продолжения обучения; отдельный `best.pt` защищён от бесконтрольной перезаписи, но является результатом *порогового скрининга*, не статистически подтверждённым чемпионом.

## Обновление с сохранением своих 170 итераций (или любого другого количества)

**Не извлекайте v0.5 поверх старой установки. Не удаляйте старую папку, даже если она называется `ChessAI-v0.3.0` и внутри уже установлена v0.4.1.** Имя старой папки может быть любым.

1. В старой Training Studio выберите «Остановить после итерации»; дождитесь завершения, закройте все её консоли и процессы обучения. Проверьте `runs/<run_id>/checkpoints/latest.pt`.
2. **Сделайте независимую резервную копию** всей старой папки, минимум `runs/` и любых персональных файлов `models/`.
3. Распакуйте ZIP v0.5 в **новую** папку `ChessAI-v0.5.0` рядом со старой.
4. В новой папке запустите **`UPGRADE_FROM_CURRENT.bat`**. Укажите *старую корневую папку* (например, `D:\Worck\Мои проекты GitHub\ChessAI_v0.4.0_Safe_Upgrade\ChessAI-v0.3.0`). Скрипт сначала делает `--dry-run`, затем просит `YES`.
5. Мигратор копирует **только `runs/`**, проверяет SHA-256 каждого файла, отказывается от конфликтов и символических ссылок, не меняет старую установку. Для вручную созданных моделей вне `runs/` сделайте отдельную копию; встроенный `models/neural_best.pt` уже находится в новом релизе.
6. Запустите **`START_CHESS_AI.bat`** из новой папки. Затем `scripts\VERIFY_PROGRESS_WINDOWS.bat`. В браузере убедитесь, что версия `BUILD 0.5.0`, нужный ID эксперимента виден и итерация прежняя (например, **170**).
7. В Training Studio выберите старый эксперимент и нажмите **«Продолжить обучение»**, а не «Новое обучение». При желании установите дебютное разнообразие в **6** полуходов. Номер checkpoint будет 171 после **одной новой** итерации.

Не запускайте v0.3/v0.4 и v0.5 одновременно в одной и той же папке с данными. Старый `UPGRADE_FROM_V0.3.bat` **не нужен**.

Миграция имеет отдельную инструкцию: [`docs/UPGRADE_TO_0.5.md`](docs/UPGRADE_TO_0.5.md). При проблеме со статусом `running` после аварии убедитесь, что процесс действительно завершён; только тогда допускается `py -3 tools\migrate_current.py --source "<OLD>" --allow-interrupted`.

## Новое в v0.5

### Evaluation 2.0: проверяем разные позиции

- В каждом тесте одна стартовая позиция разыгрывается **дважды с обменом цветов** (парный дизайн).
- Стартовые позиции генерируются воспроизводимо через короткие типовые дебютные линии и допустимые случайные продолжения (их легальность проверяет собственное C++ ядро).
- В JSON остаются `seed`, `opening_plies`, `pair_id`, `start_fen`, `opening_moves`, `unique_opening_positions`, `unique_sequences` и результаты по цветам.
- Незавершённые партии **не** записываются в поражения/ничьи, не входят в score.
- Старые отчёты v0.4 показываются с фактически вычисленной уникальностью: 40 повторённых партий нельзя считать 40 независимыми проверками.
- **Нет поддельного Elo или 95% интервала** для детерминированных коррелированных матчей. Используйте результат как диагностический, а не окончательный показатель силы.

**Сравнение старых checkpoint:** в «Диагностике модели» кнопка **«Сравнить 8 checkpoint»** или `scripts\CHECKPOINT_TOURNAMENT_WINDOWS.bat`. Это до восьми отдельных серий по 20 партий с одинаковыми дебютами и эталоном. JSON с ранжированием сохраняется в `evaluations/tournament_v05_*.json`. Победитель такой серии **не подменяет автоматически** `best.pt`: множественное сравнение по небольшому набору дебютов может дать случайного лидера.

**Как запустить:** Training Studio → «Диагностика модели» → «Запустить Evaluation». Выберите 40 (или 100) партий, лимит полуходов, 8 дебютных полуходов и эталон `baseline` / `best.pt`. Можно также запустить `scripts\EVALUATE_RUN_WINDOWS.bat`. Результаты: `runs/<ID>/evaluations/*.json`.

### Best-checkpoint / screening

- `checkpoints/latest.pt` сохраняет **модель + AdamW-оптимизатор** на последней итерации и всегда остаётся источником возобновления.
- `checkpoints/best.pt` и `best_status.json` хранят модель-кандидат, принятую пороговым сравнением с предыдущей `best.pt`. Если эталонная supervised-модель совместима, она используется для инициализации `best.pt`. Иначе инициализируем текущим `latest.pt` без заявления о качестве.
- По умолчанию каждые **10 итераций** проводится 16 парных игр для скрининга: нужна разнообразная выборка, достаточная доля завершённых пар и score не меньше **60%**. Это консервативный *практический* фильтр, но не доказательство превосходства.
- История проверок записывается в `best_history.jsonl`. Отказ в продвижении **никогда не удаляет** `latest.pt`.

### Self-Play 2.0 и корректность PPO

- Настраиваемое начало партий из разных допустимых дебютных позиций, при этом старые данные/позиции не переписываются.
- Часть игр (по умолчанию 25%) проводится против **замороженного `best.pt`** с чередованием цветов. В PPO поступают **только действия текущей модели**; чужие действия не используются как on-policy выборки.
- Незавершённые партии по-прежнему не получают вымышленной награды; благодаря возможным расширенным стартовым позициям и лиге можно тестировать влияние разнообразия на обучение.
- Диагностика отображает реально выбранное `cpu` / `cuda`, поддержку CUDA в установленном PyTorch, имя GPU и версию PyTorch. **Авто-режим не означает, что обязательно используется RTX 3050:** это зависит от установленного PyTorch и драйверов.

### Стабильность и совместимость

- Продолжение checkpoint 0.4 (кодирование `planes19_actions73_v1`, архитектура, веса и optimizer) без конвертации.
- Прежнее v0.4.1 исправление временных `PermissionError` Training Studio включено.
- Запуск и расположение `runs/` определяются по директории Python-модуля, а не по имени корневой папки; браузерный интерфейс получает явную версию и новый параметр кэширования JS/CSS.
- Сохранены шахматный поиск 1–3 полухода, UCI и прежние инструменты.

## Запуск на Windows

- Visual Studio 2022 + «Разработка классических приложений на C++», CMake, Python x64 3.11+.
- Двойной щелчок **`START_CHESS_AI.bat`**. Первый запуск компилирует C++ движок и создаёт `.venv` с пакетами из `requirements.txt`.
- В браузере: `http://127.0.0.1:8765`. При занятом порте сначала закройте старую Training Studio; при необходимости вручную выполните `.venv\Scripts\python.exe -m dashboard.server --port 8766` и откройте 8766.
- Для проверки прогресса: `scripts\VERIFY_PROGRESS_WINDOWS.bat`.
- Для оценки против базовой модели: `scripts\EVALUATE_RUN_WINDOWS.bat`.

Если CUDA не обнаружена, модель будет работать на CPU. Для использования видеокарты нужна совместимая CUDA-сборка PyTorch и драйвер NVIDIA. Рекомендации по установке должны соответствовать текущей версии PyTorch и ОС; см. официальный установщик PyTorch. Для компактной модели RTX 3050 не обязательно быстрее CPU — сравнивайте настоящие `games/sec`, `plies/sec`.

### Проверка на предоставленном checkpoint (не обещание Elo)

На сохранении `run_20261123_072154_6a110b` с `latest.pt` итерации 170 новая серия из 20 партий со стартовыми 8 дебютными полуходами и seed=27 дала **10 уникальных стартовых позиций, 20 различных последовательностей, 0 побед, 17 ничьих, 3 поражения; score 42,5%** против встроенной `models/neural_best.pt`. Старая проверка из одной позиции повторяла только две последовательности на протяжении 40 партий и не была сопоставимой независимой выборкой.

### Ограничения

- Это **не** AlphaZero / MCTS и не доказанный сильный шахматный движок. Базовый PPO не решает проблему устойчивого роста силы автоматически.
- Замороженная лига и дебютное разнообразие — экспериментальные функции; для более точного рейтинга нужны длинные турниры, несколько соперников, согласованный контроль времени/вычислений и анализ множества независимых дебютных позиций.
- Интерфейс локальный, **не имеет аутентификации**: не публикуйте сервер в открытом интернете.
- Код не предназначен для скрытой помощи в партиях людей на сайтах, где движки запрещены.
