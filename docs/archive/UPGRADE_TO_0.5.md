# Chess AI v0.5.0 — безопасное обновление уже обученного проекта

## Главное

Сохраняем `runs/<ID>/checkpoints/latest.pt` вместе с AdamW optimizer и всеми журналами. Старую установку **не редактируем**, не переписываем и не удаляем. Название старой корневой директории не имеет значения: `ChessAI-v0.3.0` с кодом v0.4.1 — допустимый исходный каталог.

## Перед обновлением

1. Закончить текущую итерацию, нажать «Остановить после итерации», закрыть Training Studio и убедиться, что больше нет запущенного `neural.selfplay`.
2. Копировать `runs` в отдельное резервное место. Сравнить наличие `run_metadata.json`, `run_state.json`, `metrics.jsonl` и `checkpoints/latest.pt` в каждом важном эксперименте.
3. Распаковать `ChessAI-v0.5.0` рядом, а не внутри старой установки.

## Обновление

В новой папке вызвать `UPGRADE_FROM_CURRENT.bat`, ввести абсолютный путь к старой корневой папке, посмотреть dry-run и ввести `YES`. Пакет копирует только файлы из `runs`. Все файлы проверяются SHA-256, результаты пишутся в `migration_reports/`. Совпадающие файлы безопасно пропускаются. Конфликтующие **не перезаписываются** — используйте чистую папку назначения.

Для PowerShell / прямого вызова:

```powershell
py -3 tools\migrate_current.py --source "D:\OLD\ChessAI-v0.3.0" --dry-run
py -3 tools\migrate_current.py --source "D:\OLD\ChessAI-v0.3.0"
```

Если процесс давно завершился аварийно, но `run_state.json` всё ещё говорит `running`, после отдельной проверки отсутствия процесса можно вызвать `--allow-interrupted`. Не используйте этот флаг при живом обучении; на перезапуске `recover_resume_files` отдельно архивирует незавершённые записи.

## После обновления

1. Запустить `START_CHESS_AI.bat`, проверить в браузере `BUILD 0.5.0`.
2. Запустить `scripts\VERIFY_PROGRESS_WINDOWS.bat`: checkpoint должен читаться с корректной `feature_version` и состоянием AdamW.
3. Выбрать старый ID, например `run_20261123_072154_6a110b`. Убедиться, что итерация **170**, если источник остановлен именно на ней.
4. Для продолжения нажать «Продолжить обучение», выбрать `1–2` дополнительные итерации, не нажимать «Новое обучение». При желании изменить дебютные полуходы с 0 на 6.
5. Проверить, что итерация продолжилась (например, 170 → 171), а прежние файлы в старой папке не изменились. `latest.pt` меняется только **в новой установке**.

Модель `best.pt` будет создана при первом продолжении из сохранённого `latest.pt` либо совместимой frozen baseline, а последующие сравнения могут обновить её. Она **не** заменяет `latest.pt` для возобновления.

## Если что-то не работает

- **`Expected v0.3.0 as source`** — запущен старый `UPGRADE_FROM_V0.3.bat`. Для v0.5 нужен `UPGRADE_FROM_CURRENT.bat`.
- **Пустая история + старая версия в шапке:** старый сервер занял порт 8765, либо браузер хранит устаревший JS. Закрыть старый процесс, открыть `/api/health`, убедиться `"version":"0.5.0"`, выполнить `Ctrl+Shift+R` или запустить новый сервер на 8766.
- **Конфликтный файл при миграции:** старые данные не изменены. Использовать чистую распакованную папку v0.5, не удалять и не переписывать checkpoint наугад.
- **CUDA unavailable:** продолжить на CPU или установить совместимую сборку PyTorch с CUDA. Установка CPU-версии Torch не способна задействовать RTX 3050 только из-за настройки `device=auto`.

## Какие файлы сохранять всегда

- `runs/<ID>/checkpoints/latest.pt`: веса + optimizer, источник продолжения
- `runs/<ID>/checkpoints/iteration_*.pt`: исторические срезы
- `runs/<ID>/run_metadata.json` и `run_state.json`: история параметров и состояние
- `runs/<ID>/metrics.jsonl`, `games.jsonl`, `experience.jsonl`, `arena_games.jsonl`: обучение и просмотр партий
- `runs/<ID>/evaluations/*.json`: отчёты
- `runs/<ID>/checkpoints/best.pt`, `best_history.jsonl`: начиная с v0.5
