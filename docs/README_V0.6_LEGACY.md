# Chess AI v0.6.0 — Learning Quality & Performance

Локальный исследовательский шахматный ИИ: C++20 Chess Core, собственная policy/value CNN (PyTorch), self-play PPO и Training Studio в браузере. Релиз продолжает v0.5.0, **не меняет формат модели** (`planes19_actions73_v1`) и не требует сброса истории обучения.

> **Сила игры пока не подтверждена.** На присланной оценке v0.5.0 кандидат набрал 45,8% против исходной модели в 500 партиях, 89,6% исходов — ничьи. Новые методы направлены на диагностику и снижение рисков деградации, но не гарантируют роста Elo. Эта сборка не содержит самых свежих весов твоего ПК: они переносятся локальным мигратором.

## 1. Обновление с сохранением данных — ОБЯЗАТЕЛЬНО

1. В старой Training Studio нажми **«Остановить после итерации»**. Дождись окончания и закрытия всех старых процессов Python / ChessAI. **Не прерывай создание `latest.pt`**.
2. Сделай резервную копию всей предыдущей папки или как минимум `runs/` и пользовательских `models/`. Проверь, что `runs/<ID>/checkpoints/latest.pt` существует.
3. Распакуй ZIP в новую отдельную папку `ChessAI-v0.6.0`. Не распаковывай поверх v0.5.0.
4. Запусти `UPGRADE_FROM_CURRENT.bat`, введи полный путь к *корню* предыдущего Chess AI. Например, папка может называться `ChessAI-v0.3.0`, хотя код внутри уже версии v0.5.0 — это поддерживается.
5. Мигратор выполняет dry-run, сверяет SHA-256 и копирует **только пользовательские файлы внутри `runs/`**, не удаляя и не изменяя старую установку. При конфликте останавливается, ничего не перезаписывая. Модели, сохранённые вне `runs/`, нужно переносить отдельно после проверки.
6. Запусти `START_CHESS_AI.bat` из новой папки. В браузере проверь `BUILD 0.6.0`, ID эксперимента и **неизменившийся номер итерации**. Проверь checkpoint скриптом `scripts/VERIFY_PROGRESS_WINDOWS.bat`.
7. Выбери прежний эксперимент → **«Продолжить обучение»** → 2 тестовые итерации. После первой сохранённой итерации `latest.pt` уже будет содержать модель вместе с состоянием оптимизатора.

**Не запускай одновременно старую и новую Training Studio на одном порту `8765`.** Старый сервер может оставаться активным и показывать устаревший интерфейс.

Подробная инструкция и разбор ошибок: [`docs/UPGRADE_TO_0.6.md`](docs/UPGRADE_TO_0.6.md).

## 2. Что нового в v0.6.0

### Repetition diagnostics и небольшой anti-reversal bias

- `termination_reasons` в каждой итерации: мат, пат, повторения, недостаточный материал, незавершённость. В отчётах матчей — те же причины, независимо от того, кто выиграл.
- `position_revisits`: число повторных посещений позиции по FEN (первые четыре поля). Это **приблизительный диагностический показатель**: FEN может различать en passant там, где взятие невозможно.
- `--repetition-penalty 0.12`: небольшой штраф логиту **немедленного возврата собственной фигуры на предыдущую клетку**. Он применяется только при стохастическом сборе тренировочных партий для текущей модели; сам ход остаётся разрешённым, движок может выбрать его и поставить мат / спастись ничьёй. Проверочные Evaluation играются **без штрафа**. Это не универсальная «антиничейная» награда и не гарантия снижения ничьих.
- PPO использует **тот же скорректированный policy-logit**, что использовался при сборе хода, поэтому отношение вероятностей не становится заведомо некорректным.

### PPO Stability

- `--target-kl 0.035`: ранняя остановка следующих минибатчей, если оценка approximate KL превышает порог. Первая итерация обновления может пройти, даже если данные имеют большой KL, чтобы не заблокировать весь запуск.
- `--grad-clip 1.0`: ограничение нормы градиента; значения `NaN` / бесконечность приводят к исключению **до** обновления оптимизатора.
- В `metrics.jsonl`, CSV и Training Studio добавлены `approx_kl`, `clip_fraction`, `grad_norm`, `early_stopped_kl`. Эти показатели помогают искать нестабильность, но не доказывают, что сеть стала лучше играть.

### Self-Play Historical League

- `--league-pool-size 4`: одна замороженная `best.pt` плюс разнообразные старые `iteration_*.pt`, при совместимой архитектуре. История содержит имя выбранного соперника.
- На партии против замороженных соперников используется **on-policy PPO только для ходов текущей нейросети**. Опыт старых моделей не выдаётся за собственный.
- Пул пересобирается после новых архивных checkpoint или продвижения `best.pt`. Базовый `latest.pt` и старые архивы не переписываются лигой.

### Holdout Evaluation и Best Guard

- В интерфейсе Evaluation можно выбрать два воспроизводимых набора: `selection` (для отбора checkpoint) и `holdout` (другое пространство seed, по умолчанию). **Разделение seed не означает математически независимых партий или защиту от всех совпадений дебютов.**
- Прежде чем продвигать кандидата в `best.pt`, пороговый скрининг по возможности должен быть пройден в **обоих** наборах. Это эвристика контроля качества, не статистическая сертификация превосходства.
- Сохранились парные матчи с обменом цветами, показатели уникальности стартов/партий и история турниров checkpoint.

### Производительность CPU/CUDA

- Выбор ходов оптимизирован: policy/value-выходы одной батчевой операции переносятся на CPU **одним копированием**, вместо многократных отдельных синхронизаций для каждой доски. Действия по-прежнему выбираются только из легальных ходов.
- `scripts/BENCHMARK_HARDWARE_WINDOWS.bat` сохраняет `diagnostics/hardware_benchmark.json`: времена прямого прохода и обратного прохода модели для батчей 1 / 8 / 32 / 128, скорость C++ bridge без нейросети.
- `scripts/AUDIT_COLOR_WINDOWS.bat` сравнивает прогнозы Value на настоящих FEN и их преобразованиях с поворотом / сменой цвета, сохраняя `runs/<ID>/diagnostics/color_audit.json`. Дисбаланс **не доказывает ошибку** кодирования.
- **Не запускаются внешние API, не устанавливаются автоматически CUDA-драйверы**. Если PyTorch сообщает `+cpu`, обучение происходит на CPU. Для RTX 3050 нужна совместимая CUDA-сборка PyTorch и драйвер. GPU-бенчмарк выполняется только при `torch.cuda.is_available()`.

## 3. Windows: команды

```bat
START_CHESS_AI.bat
scripts\VERIFY_PROGRESS_WINDOWS.bat
scripts\BENCHMARK_HARDWARE_WINDOWS.bat
scripts\AUDIT_COLOR_WINDOWS.bat
scripts\EVALUATE_RUN_WINDOWS.bat
scripts\CHECKPOINT_TOURNAMENT_WINDOWS.bat
```

Для ручного запуска Training Studio на другом порту:

```bat
.venv\Scripts\python.exe -m dashboard.server --port 8766
```

Нужны Python x64 3.11+, CMake, Visual Studio с компонентами C++20. Первый запуск создаёт `.venv` и собирает шахматное ядро. Шахматные партии в реальных интерфейсах и скрытая помощь на чужих аккаунтах этим релизом **не реализованы**.

## 4. Продолжение обучения через командную строку

```bat
.venv\Scripts\python.exe -m neural.selfplay --resume --engine build\Release\chessai.exe --out runs\run_20261123_072154_6a110b --iterations 2 --games-per-iteration 16 --parallel 8 --max-plies 400 --opening-plies 8 --league-fraction 0.25 --league-pool-size 4 --repetition-penalty 0.12 --target-kl 0.035
```

Это **пример** для существующего эксперимента, если путь и параметры соответствуют. Перед ручным запуском проверь команды/пути, сохранённые настройки и отсутствие другого активного обучения. Для обрыва партии по лимиту исход **не превращается** в ничью и не используется в наградах PPO.

## 5. Как проверить версию и тесты

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
python -m unittest discover -s tests -v
node --check dashboard/ui/app.js
```
