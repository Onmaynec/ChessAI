# Deep Search Engine v0.9.2

## Что меняется

Новый C++ поиск используется в UCI и локальном interactive play. Старый search_baseline сохранён для сравнения и прежнего teacherdata. ChessNet, кодировка, PPO и checkpoint не меняются. Гибридный Python-инференс продолжает оценивать легальные дочерние позиции через UCI; получает фактическую PV и счётчики нового поиска. Номинальный search_depth включает ход из корня гибрида, chosen_completed_depth — завершённую глубину выбранной ветви; доказанный мат может завершить итерации раньше. Старая версия UCI без PV поддерживается, но не даёт новых счётчиков. Незавершённая оценка без доказанного мата отклоняется, работает существующий fallback.

## Алгоритм

- Iterative deepening 1..12 полуходов, alpha-beta/PVS, переоценка перспективной ветви.
- Zobrist XOR по каноническому ключу ядра (фигуры/ход/рокировки/легальное en passant); таблица 16 MiB по умолчанию, Hash 0..256 MiB. Таблица локальна одному поиску. Повторное использование score bounds только при совпадающем контексте обратимых ходов и halfmove, для иных контекстов — только сортировка.
- MVV-LVA взятий, продвижения, killer moves, history heuristic. Mate-distance normalization в TT.
- Quiescence: взятия и превращения, при шахе все легальные ответы; тихий предел 8, предел шаховой цепочки 24 с отменой незавершённой итерации. Без stand-pat в шахе при включённом Q. Не эквивалентно исчерпывающему поиску такой глубины.
- Мат/пат проверяются раньше правил ничьей. История повторений передаётся из UCI position ... moves; один FEN не восстанавливает предысторию. Python гибрид использует отдельные FEN дочерних позиций и существующий штраф повторений — история до FEN не реконструируется.
- Материал + мобильность, центральные поля, пара слонов, изолированные/сдвоенные/проходные пешки, поддержка пешек, вертикали ладей, безопасность короля, переход к эндшпильной оценке. Коэффициенты эвристические, не обученные; силу проверяем матчами.
- Лимиты узлов, movetime и упрощённое распределение шахматных часов; при отмене возвращается последняя завершённая итерация (при нулевой глубине — легальный аварийный ход). Время проверяется между узлами, не hard real-time. UCI остаётся синхронным: асинхронный stop/ponder/infinite не реализованы. score cp сохраняет прежний формат, в том числе внутренний mate sentinel ±30000.

## Сборка и проверка

Обновление C++ требует пересборки. Установщик выполняет CMake/CTest на отдельной временной сборке перед заменой файлов и проверяет протокол UCI, затем устанавливает проверенный exe. При ручном git pull запустите scripts/build_windows.bat. Не используйте старый exe для сравнения v0.9.2.

```powershell
.\build\Release\chessai.exe search-bench 3
.\build\Release\chessai.exe search-bench 3 "3r2k1/8/8/3p4/8/8/8/3Q2K1 w - - 0 1"
```

UCI: position startpos, go depth 4, go movetime 500, go nodes 5000, setoption name Hash value 32. info содержит завершённую depth, cp, nodes, time (ms), nps, qnodes, tthits, pv. Команда search-bench печатает старый baseline и новый поиск при одинаковой номинальной глубине, не доказывает прирост силы (Q и оценка меняют объём работы и cp). Запустите v0.9.1 Intelligence Benchmark на прежних checkpoint до/после, одинаковые suite/seed/depth/device, отдельно policy и hybrid. Не объявляйте рейтинг выросшим, пока нет сравнимых данных.

Тесты C++: прежний perft и правила плюс легальность PV, матовые позиции, quiescence, лимит узлов, TT on/off, ничьи, перспектива оценки. Python: совместимость парсера и фактическая PV. Windows, полный турнир и качество эвристик требуют локального подтверждения.
