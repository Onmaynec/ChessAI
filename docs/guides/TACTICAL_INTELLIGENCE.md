# Tactical Intelligence v0.9.3

Экспериментальное специализированное обучение, полностью локальное. Запуск START_TACTICAL_TRAINER.bat после остановки PPO и Vision. По умолчанию latest.pt прежнего run, можно указать иной checkpoint. Генератор создаёт случайные разреженные окончания и позиции из легальных случайных партий, оценивает все легальные дочерние позиции C++ поиском v0.9.2 (depth 2), сохраняет доказуемый мат в один и учительские ответы/разницу оценок. Мат более чем в один ход — результат ограниченного поиска, не отдельное формальное доказательство. Геометрические мотивы — кандидаты, не доказательство выигрыша. Ограничение числа попыток и категории; фактический объём/распределение в dataset_meta.json, возможен неполный набор. Не используется для PPO напрямую.

Наборы разделены по независимым сгенерированным траекториям; исключаются дубликаты FEN и отражения, известные позиции benchmark/suite_v*.json. Проверка не доказывает отсутствие иных исторических совпадений. Validation используется для выбора эпохи, не независимый holdout. Тренер masked multi-target policy CE + слабая дистилляция исходной policy и value consistency, BN running stats frozen, AdamW отдельный. Исходник не меняется. candidate.pt только при улучшении validation; это экспериментальный inference checkpoint, не PPO resume. Не подменять latest/best. Сравнить с исходником: python -m benchmark.run --run runs/... --engine build/Release/chessai.exe --output benchmark_reports/tactical_compare --profile standard --agents latest.pt --candidate tactical_experiments/.../train/candidate.pt . При отсутствии candidate улучшения не подтверждены.

Benchmark V2 по умолчанию, 26 задач; V1 доступен через --suite v1 для воспроизведения. Исправлены оба допустимых взятия связанного ферзя, добавлены 4 отражённых пары на маты, взятие и защиту. Это маленький набор, не 500 задач. В отчёте причины завершения партий, включая повторения. PPO rewards и правила ничьей не изменены: нужны отдельные контролируемые эксперименты. Использование только в локальных шахматных тестах. Новых зависимостей нет; пересборка C++ не нужна.

В исходной версии 0.9.3 в конце BAT при наличии candidate предлагается парное сравнение с исходным стандартным alias из run/checkpoints; при произвольном пути к checkpoint сравнение следует запустить вручную. В отчёте явно отмечается пропущенный аудит. Дополнительно гибрид отдаёт геометрические признаки в существующее поле motifs и tactical_evidence, а при сбое поиска сохраняет приоритет уже доказанного немедленного мата. Это не обучение в реальном времени. Отдельная классификация перегрузки, промежуточных ходов и профилактики пока не реализована; обучение reward PPO не менялось.


## v0.9.3.1 — Tactical Learning Overhaul

Первый эксперимент показал 2/16 до и после, всего 8 шагов AdamW. Новый START_TACTICAL_TRAINER.bat запускает меню новой сессии или возобновления. Pilot 500+100 / 20 эпох, Standard 2000+400 / 25, Full 5000+1000 / 30; batch 64, LR по умолчанию 1e-4, ввод 3e-5–3e-4, глубина учителя 3 (можно 4/5). Full — дорогой CPU-эксперимент, начинать с Pilot. Не обещается достижение заданных метрик. Профили задают предел эпох, early stopping может завершить раньше. При полном Full и 30 эпохах — 2370 шагов.

Генерация: неизменяемая конфигурация, pool.jsonl с fsync после каждой принятой строки, generation_state.json с курсором, seed на попытку. При Ctrl+C/сбое продолжение через пункт 2 и путь из консоли; при исчерпании попыток можно увеличить общий лимит. Незавершённый набор не передаётся в обучение. Сначала дешёвый поиск depth 2, затем перепроверка всех ходов при целевой глубине, кроме доказанных матов в один. Дополнительные разреженные позиции содержат несколько фигур. Ограничение доминирующего класса 25% (для малых наборов минимум 6); редкие категории не гарантируются. Финальное стратифицированное разбиение с точным размером validation, обе части каждой категории по возможности, отчёт о пропущенных категориях. Не гарантируется отсутствие иных исторических/родственных позиций. Известные benchmark-сигнатуры и отражения исключены; хеши suite фиксируются в журнале.

Тренер кодирует позиции один раз, вычисляет батчи, на каждой эпохе взвешивает ошибки training-only: низкая вероятность правильных ходов и редкие классы получают больший вес (0.5–4). Все train-позиции проходят каждую эпоху. Validation не используется для hard mining. Сохраняются Top-1/3/5, MRR, средний лучший ранг, суммарная вероятность допустимых ответов и -log этой вероятности; по категориям и всему набору. Отдельные train-метрики помогают обнаружить переобучение. ReduceLROnPlateau по MRR (factor .5, patience 2), early stopping 6 эпох без улучшения лексикографического (top1, MRR, -NLL) показателя. Кандидат только при строгом улучшении validation top1. Повторные эксперименты на той же validation не являются независимым тестом.

training_state.pt хранит отдельный optimizer/scheduler/RNG/model/history, атомарно по завершении эпохи; прерванная эпоха повторяется, не mid-batch resume. При изменении исходного checkpoint, engine, dataset или конфигурации возобновление запрещено. candidate.pt публикуется только после завершения эксперимента, не PPO checkpoint. Исходная модель, runs, optimizer PPO не меняются. Сравнение через benchmark.run с --agents latest.pt --candidate <путь> --profile standard --skip-audit (диагностический режим; для аудита убрать флаг). Не копировать candidate в latest. Старый dataset_v1 с complete=true можно вручную использовать с новым CLI, но его малая выборка остаётся недостатком. C++ не меняется.

Пример ручного запуска:
```powershell
python -m neural.tactical_data --engine build/Release/chessai.exe --output tactical_experiments/pilot/data --count 600 --validation-count 100 --depth 3 --attempts 30000
python -m neural.tactical_train --source runs/run_20261123_072154_6a110b/checkpoints/latest.pt --dataset tactical_experiments/pilot/data/dataset.jsonl --engine build/Release/chessai.exe --output tactical_experiments/pilot/train --epochs 20 --batch 64 --lr 0.0001
```
Для возобновления каждого этапа добавьте --resume с прежними параметрами. У генератора можно увеличить --attempts. Профиль Full — цель объёма, а не обещание времени генерации.

В новом меню при наличии candidate и стандартном alias в run/checkpoints предлагается диагностический Standard-турнир source/candidate (6 стартов, обмен цветов; тактические задачи в обоих режимах, турнир policy). Для произвольного checkpoint сравнение вручную. Без аудита это диагностика, не доказательство независимого holdout.
