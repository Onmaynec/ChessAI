# Chess AI Changelog

## v0.7.0 — Training Performance & Intelligence (2026-11-23)

- Полностью воспроизводимая **lossless** gzip-архивация `experience.jsonl`, `games.jsonl`, `arena_games.jsonl`. Контроль исходного SHA-256 через обратную распаковку; сжатие после commit; доступ к старым играм через API.
- Потоковое восстановление после прерванных логов без гигабайтных списков Python. `latest.pt`, `best.pt`, метрики и исторические checkpoint никогда не удаляются архиватором.
- Непрерывное пополнение партий во время self-play вместо блоков до завершения последней игры. GPU инференс объединяет позиции текущих активных партий.
- Несколько независимых C++ ChessBridge-процессов с управляемым `--bridge-workers` (по умолчанию 2). В полных метриках — фазы генерации позиций/ходов, инференса, PPO и арен.
- Training Studio: Storage и Performance, ручное безопасное сжатие только при остановленном обучении, просмотр архивных партий.
- Мигратор копирует старый эксперимент с SHA-256 и при наличии `.venv-cuda` сохраняет путь к прежнему интерпретатору вместо повторного скачивания CUDA PyTorch.
- Проверка архива настоящего пользователя: 325,82 → 92,29 МиБ, 703 470 позиций, успешное возобновление checkpoint 170 → 171 с оптимизатором. Ускорение на RTX 3050 ещё не измерено.
- Обновление кода не утверждает улучшение шахматной силы или Elo.


## v0.6.0 — Learning Quality & Performance (2026-11-23)
- Расширенный self-play: запись причин завершения и повторных посещений FEN, опциональный train-only штраф за немедленный обратный ход с корректной вероятностью в PPO, без изменения результата партий.
- Стабилизация PPO: approximate KL, clip fraction, норма градиента, ранняя остановка, контроль нечислового loss/gradient.
- Историческая лига: best.pt + равномерно выбранные checkpoint, смена соперников при появлении новых архивов, журнал выбранного оппонента; on-policy учёт только текущей сети.
- Evaluation: раздельные воспроизводимые seed-наборы selection / holdout, полноценный отчёт причин завершения, двухэтапная эвристическая проверка перед best promotion.
- Производительность: один перенос батча policy/value с CPU/GPU для выбора ходов, CPU/CUDA бенчмарк по размерам батчей; цветовая проверка Value через синтетическую инволюцию FEN.
- Training Studio: диаграмма причин завершения, метрики KL/clip, предупреждения, показ результатов локальных аппаратных тестов, новые поля конфигурации, версия BUILD 0.6.0.
- Безопасное обновление: новый проект отдельно от старого, SHA-256 копирование runs/, никакого переобучения с нуля, старая папка остаётся нетронутой. Старый feature_version не изменён.
- Все улучшения экспериментальны; рост шахматной силы и ускорение на RTX 3050 не заявляются без бенчмарков пользователя.

## v0.4.0 — Safe Upgrade, Neural Search & Diagnostics (2026-11-23)

### Safe Upgrade
- Новый мастер миграции `UPGRADE_FROM_V0.3.bat` копирует **из v0.3 в отдельную установку v0.4** каталоги `runs`, `models`, `output`.
- До записи: dry-run, SHA-256, проверка версий и активных запусков, запрет конфликтов и небезопасных символьных ссылок.
- После копирования: отчёт, контроль размеров и хешей, повторяемый безопасный запуск, старый проект не меняется.
- `tools/verify_progress.py` проверяет совместимость `feature_version`, сохранённую модель и `AdamW` optimizer.
- `recover_resume_files` изолирует незавершённые записи после сбоя и сохраняет исходные логи в `recovery`. Номер checkpoint используется как граница продолжения.

### Neural Search
- `neural/search.py` добавляет неглубокий minimax (1–3 полухода) с policy-guided Top-K branching на продолжениях.
- На первом полуходе просматриваются ВСЕ легальные ходы, поэтому слабая policy не исключает простой мат только из-за низкого prior.
- Терминальные оценки (`checkmate` / ничья) приходят от C++ шахматного ядра, нет выдуманных результатов.
- Интерфейс CLI: `scripts/NEURAL_SEARCH_WINDOWS.bat`.
- Ограничение: это не MCTS, не оптимизированный alpha-beta и не самоигра с поиском по умолчанию.

### Evaluation & Training Studio
- Независимый скрипт `neural/evaluation.py`: парные по цветам матчи против неподвижной supervised baseline, отдельные JSON-отчёты в `runs/<ID>/evaluations/`.
- Раздел «Диагностика модели»: завершение партий, позиции с наградой, тренды Value MSE, результат контрольных матчей, широкий консервативный диапазон Хёффдинга.
- Предупреждения о большом числе оборванных партий и недостаточной выборке arena.
- API `/api/analysis`, данные с диска; новая страница UI с графиками и рекомендациями.
- Исправлен статус interrupted, когда прошлый запуск сохранил `running`, но его процесса уже нет.
- При продолжении через интерфейс можно менять лимит полуходов, а изменение фиксируется в истории параметров без сброса checkpoint.
- Демо из `runs/demo_endgame` перемещено в `examples/demo_endgame`, чтобы при обновлении не конфликтовать с одноимённым настоящим экспериментом.

### Проверки
- 23 Python unit/integration-теста, C++ CTest; отдельный end-to-end перенос реальных файлов v0.3.0 + продолжение checkpoint 2 → 3.
- Проверка короткой endgame-оценки и поиска мата в один ход.
- Тестирование в Linux CPU; проверка Windows batch и GPU CUDA — на пользовательской системе.
